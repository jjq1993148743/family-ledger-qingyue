# 记账功能业务用例设计

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-04 |
| 项目 | 家庭收支本 · 青月版（微信小程序） |
| 硬约束 | 纯本地存储、不联网、不用云开发、不用后端（`README.md:3`） |
| 交付形态 | 业务用例：谁 · 在哪个页面 · 能干什么 · 达到什么目的 |
| 本轮状态 | 仅设计，未改任何业务代码 |
| 修订一 | 2026-11-04：去掉多人协作与成员权限体系，改为「账本分享 + 分享时勾选可否更改」 |
| 修订二 | 2026-11-04：可更改的副本改动必须留痕（谁、什么时候），全账本增加一条完整操作流水 |

## 一、范围裁定

| 项 | 结论 | 理由 |
|---|---|---|
| 截图 `OCR`（图片文字识别） | 不做 | 用户点名砍掉 |
| 自动同步微信 / 支付宝 / 银行流水 | 不做 | 用户点名砍掉；最麻烦的一档：要登录授权、各家账单格式不一、必须联网加后端、隐私合规、接口一变就失效 |
| 多币种 | 不做 | 统一人民币 |
| 社区 | 不做 | 与记账无关 |
| `AI`（人工智能） | 不做 | 连带的「语音 / 一句话智能解析」一并砍掉，本质靠 `AI`，不做半吊子 |
| 多人协作 / 成员权限体系 | 不做 | 用户点名砍掉；不建账号、不跨设备同步、不做实时共享 |
| 账本分享 | **做** | 分享账本时当场勾选「允许对方更改」；不勾则对方只读，勾了则可改 |
| 操作留痕 + 整体操作流水 | **做** | 可更改的副本每次改动记下「谁、什么时候、对哪笔、改前改后」；全账本一份按时间排的完整流水 |
| 只读副本的「访问记录」 | 做不到 | 本地无服务端，对方什么时候打开副本这边不可能知道；只保证改不了、入口隐藏 |
| 除以上不做项 | 全做 | 用户确认「其他的都要」 |

说明：原有 `member`（成员：我 / 家人 / 共同）只是**账目归属标签**，用来做统计，不是账号，也不是协作身份，保留不动。

## 二、角色

| 角色 | 是谁 | 权限边界 |
|---|---|---|
| 使用者 | 本机使用这个小程序的人 | 记、改、删、看、管配置、发起分享、看操作流水、合并回传 |
| 分享接收方 | 拿到分享文件、在自己手机上导入的人 | 导入成**独立副本**；不勾可改则只读，勾了可改就能记改删且每次改动自动留痕，可把改动与流水回传 |
| 系统 | 小程序自身，非真人 | 补记周期账、算预算、去重、生成分享 / 导出文件、自动追加操作流水 |

## 三、页面

| 页面 | 状态 | 文件 | 定位 |
|---|---|---|---|
| 账本页 | 现有，增强 | `miniprogram/pages/ledger/ledger` | 记一笔 + 本月概览 + 预算余量 |
| 流水页 | 新增 | `miniprogram/pages/stream/stream` | 全部账目、日历、搜索、编辑、撤销 |
| 月结页 | 现有，增强 | `miniprogram/pages/monthly/monthly` | 月度复盘、占比、预算执行、下钻 |
| 设置页 | 新增 | `miniprogram/pages/settings/settings` | 分类、账户、账本、模板、周期、预算、导出、分享账本、回传合并 |
| 操作流水页 | 新增（设置页二级入口） | `miniprogram/pages/audit/audit` | 全账本操作留痕：谁、何时、对哪笔、做了什么、改前改后 |

页面注册见 `miniprogram/app.json:2`，底部 `Tab`（标签页）见 `miniprogram/app.json:13`，建议扩为四个：账本 / 流水 / 月结 / 我的；操作流水页走「我的」二级入口，不占 `Tab`。

## 四、业务用例

| 编号 | 谁 | 在哪个页面 | 可以干什么 | 达到什么目的 |
|---|---|---|---|---|
| A1 | 使用者 | 账本页 | 切支出 / 收入，输金额（支持 `12+8` 直接算），选分类、账户、成员、日期（可补昨天以前）、填备注、附票据照片，点「记下」 | 一次把一笔真实消费记全，不用回家补、不漏字段 |
| A2 | 使用者 | 账本页 | 选模板（买菜 / 通勤 / 工资）一键带入金额、分类、账户、备注，只改金额就存 | 高频固定支出不用每次重填 |
| A3 | 使用者 | 账本页 | 记完保留上次分类、账户、成员，只清金额和备注 | 连着记几笔不重复选 |
| A4 | 使用者 | 账本页 | 顶部看本月收入 / 支出 / 结余、预算剩余，超支标红 | 记之前就知道这个月还剩多少能花 |
| A5 | 使用者 | 账本页 | 切当前账本（日常 / 旅行 / 装修） | 专项花费不混进家庭日常账 |
| A6 | 系统 | 账本页 | 冷启动 / 回前台时按周期规则补记到期账，同日同规则只补一次 | 房租、工资不因忘记打开而漏记 |
| A7 | 使用者 | 账本页 | 点最近几笔进详情，直接编辑或删除 | 记错当场改，不用翻二级页 |
| B1 | 使用者 / 分享接收方 | 流水页 | 按日分组看全部账目（不再只显 8 笔），每日小计收入 / 支出 | 完整还原钱怎么花的 |
| B2 | 使用者 / 分享接收方 | 流水页 | 日历视图点某天看当天明细、跨天补记 | 对账、想起漏记的那天 |
| B3 | 使用者 / 分享接收方 | 流水页 | 按分类 / 成员 / 账户 / 账本 / 类型 / 日期 / 金额区间 / 关键词筛选 | 从几百笔里一秒找到「上周给爸买药那笔」 |
| B4 | 使用者 / 分享接收方（限可改副本） | 流水页 | 编辑任意一笔：金额、分类、账户、成员、日期、备注、票据 | 记错、选错、输错都能纠正 |
| B5 | 使用者 / 分享接收方（限可改副本） | 流水页 | 删除后 5 秒内撤销，或进回收站保留 7 天 | 手滑删了不丢数据 |
| B6 | 使用者 / 分享接收方 | 流水页 | 点开票据照片看原图 | 核对小票、报销有凭 |
| B7 | 分享接收方 | 流水页（导入的副本） | 导入后按 `editable`（可否更改标记）：不勾只读，记改删入口全隐藏、强行触发也拦住；勾了可改，每次改动自动按 `actor`（操作人署名）+ 本地时间写进操作流水 | 只读就是真只读，能改就笔笔留痕，谁在什么时候动的说得清 |
| C1 | 使用者 / 分享接收方 | 月结页 | 左右切月份，看收入 / 支出 / 结余、笔数 | 月底复盘有个准数 |
| C2 | 使用者 / 分享接收方 | 月结页 | 按分类 / 成员 / 账户 / 账本看支出占比与排行 | 知道钱主要花在哪个口子、谁花的 |
| C3 | 使用者 / 分享接收方 | 月结页 | 看总预算与分类预算执行、超支标红、对比上月趋势 | 下个月知道该收哪一刀 |
| C4 | 使用者 | 月结页 | 点分类下钻到该分类的流水 | 从「伙食花了 2000」直接看到哪笔记多了 |
| D1 | 使用者 | 设置页 | 增删改分类（名称 / 图标 / 颜色 / 排序），支出收入各一套 | 分类贴合自家口径，不再被写死的 7 + 5 个困住 |
| D2 | 使用者 | 设置页 | 管账户（现金 / 微信 / 支付宝 / 银行卡），可停用不删历史 | 记账能选资金出处，停用旧卡不丢旧账 |
| D3 | 使用者 | 设置页 | 管账本（建 / 改名 / 切换 / 删，删除二次确认并说明数据去向） | 旅行、装修专项账分开算 |
| D4 | 使用者 | 设置页 | 管模板（把常记的一笔存成模板、排序、删除） | 把 A2 的提速能力自己攒出来 |
| D5 | 使用者 | 设置页 | 管周期账（金额 / 分类 / 账户 / 周期 / 起始日 / 启停） | 房租、工资、话费不用月月手敲 |
| D6 | 使用者 | 设置页 · 分享账本弹层 | 选账本 → 勾「允许对方更改」→ 给这份副本填个署名（用于留痕，如「给爱人的副本」）→ 选时间范围或全部 → 生成带操作流水的分享文件 → 转发微信 | 一次把一本账交出去，改不改、算谁改的，当场全定好 |
| D7 | 使用者 | 设置页 | 设总预算、各分类预算、超支提醒开关 | 把 A4 / C3 的阈值定下来 |
| D8 | 使用者 | 设置页 | 导出 `CSV`（逗号分隔表格，按时间 / 账本筛选）并转发或复制；导入备份恢复，也可导入别人分享来的账本 | 数据只在本地，换手机、清缓存也不丢；别人发来的账本也能收 |
| D9 | 使用者 | 设置页 | 看本地占用、清理票据图片、清空账本数据（操作流水只追加不随清空消失） | 本地存储不被图片撑爆，留痕不被顺手抹掉 |
| D10 | 分享接收方 | 设置页 · 导入 | 导入分享文件成一本新的独立账本副本，按 `editable` 决定可改或只读，同时接住对方带过来的历史操作流水 | 拿到就能看或就能补，且不碰原来那本账 |
| D11 | 分享接收方 → 使用者 | 设置页 · 回传 / 合并 | 接收方把「改动 + 操作流水」导成文件发回；原使用者导入后合并：同一笔两边都改过，按时间戳后改覆盖，双方版本都留在流水里 | 不联网也能看到对方改了啥、谁在什么时候改的，且不静默丢数据 |
| E1 | 使用者 / 分享接收方 | 操作流水页 | 按时间倒序看整本账从建账到现在的全部操作：谁、什么时候、对哪笔、做了什么（记一笔 / 改 / 删 / 分享 / 导入 / 合并 / 周期补记）、改前值改后值 | 账上任何变动都能追到人追到时间，不靠回忆 |
| E2 | 使用者 / 分享接收方 | 操作流水页 | 按操作人、动作类型、时间范围、关键词筛选，点一条跳到对应那笔账 | 几百条流水里一秒定位「这数是谁改的」 |
| E3 | 使用者 / 分享接收方 | 操作流水页 | 单独导出操作流水，或随分享文件一起带走 | 换设备、发给别人时留痕不丢 |
| E4 | 系统 | 所有发生写操作的地方 | 每次新增 / 修改 / 删除 / 撤销 / 分享 / 导入 / 合并 / 周期补记，自动追加一条流水：只追加，界面不提供编辑删除，账目删了流水仍在 | 留痕靠系统自动记，不靠人自觉，也不会被顺手抹掉 |

## 五、约束与落地替代

| 想做的事 | 硬约束 | 落地办法 |
|---|---|---|
| 「别人访问」 | `README.md:3` 纯本地不联网；`wx.shareAppMessage`（分享小程序卡片接口）只带链接，带不过本地账目，对方打开只会看到他自己手机上的数据 | 走 `wx.shareFileMessage`（转发文件到微信会话）发文件，对方用 D8 导入成独立副本；**访问的是副本，不是你手机上的账本** |
| 只读副本的「访问记录」 | 无服务端，对方何时打开这边无从得知 | 做不到自动留痕；只保证改不了、入口隐藏、强行触发被拦，且不产生改动流水 |
| 「谁」怎么来 | 无账号、不联网、不授权，拿不到微信昵称 | 分享时填署名写进文件头 `actor`，每条流水带它；这是留痕署名，不是实名认证 |
| 「什么时候」 | 无服务端时间 | 用设备本地时间；可被系统时间影响，属于留痕，不是审计级证据 |
| 整体操作流水怎么看到 | 副本在对方手机，本机看不到对方改动 | 流水随账本文件走：谁拿到都能看到从建账到现在的完整流水；想让原使用者也看到，靠 D11 手动回传合并，不做实时同步 |
| 合并冲突 | 两边都能改同一笔 | 按时间戳后改覆盖，双方版本都写进流水，不静默丢；冲突条目在 E1 里可筛出来 |
| 流水防篡改 | 纯本地文件无服务端鉴权 | 只追加、界面不提供改删；不做加密防篡改 |
| 语音 / 一句话 / `OCR` / 流水自动同步 / 多币种 / 社区 / `AI` | 用户点名砍掉；`README.md:3` 纯本地不联网 | 不做，不预留入口 |
| 票据照片 | `wx.setStorageSync`（微信本地缓存接口，`miniprogram/utils/store.js:30`）容量有限 | 图片存小程序本地永久文件，账目只存文件路径，D9 可清理 |
| 周期账「自动」 | 小程序无后台常驻 | 冷启动 / 回前台补记 + 去重（A6），不做定时推送 |
| 超支「提醒」 | 无订阅消息、无后端 | 页内标红（A4 / C3），不做系统通知 |
| 导出 `CSV` | 小程序无浏览器下载 | 生成文件后转发到微信或复制文本（D8） |
| 老数据兼容 | 现有记录字段固定（`miniprogram/pages/ledger/ledger.js:102`），日期写死今天（`:104`），只能删不能改（`miniprogram/utils/store.js:34`） | 新字段读取时补默认值，不迁移；`month`（月份）按 `date`（日期）重算；老账目不伪造历史流水 |

## 六、数据字段变化

| 新增字段 | 中文 | 用在哪 | 老数据怎么处理 |
|---|---|---|---|
| `bookId` | 账本标识 | A5、D3、B3、C2、D6 | 默认「日常账本」 |
| `account` | 账户 / 支付方式 | A1、D2、B3、C2 | 默认「现金」 |
| `imagePath` | 票据图片路径 | A1、B4、B6、D9 | 空 |
| `updatedAt` | 最后修改时间 | B4 | 取 `createdAt`（创建时间） |
| `templateId` | 模板来源 | A2、D4 | 空 |
| `recurringId` | 周期规则标识 | A6、D5 | 空 |
| `deletedAt` | 删除时间（回收站） | B5 | 空 |
| `editable` | 可否更改（**分享文件头标记，不进账目记录**） | D6、D10、B7 | 无老数据；缺省按只读处理 |
| `actor` | 操作人署名（**分享文件头标记，不进账目记录**） | D6、B7、E1、D11 | 缺省「本机使用者」 |
| `operations` | 操作流水数组（**跟随账本文件，不进单条账目**） | E1–E4、D11 | 老数据补空数组，已有账目不伪造历史 |

`operations` 每条含：`id`（流水号）、`actor`（谁）、`at`（时间）、`action`（动作）、`entryId`（哪笔账）、`before`（改前值）、`after`（改后值）、`source`（来源账本 / 副本）。

## 七、验收口径

| 编号 | 条件 |
|---|---|
| 1 | 能把一笔账记到昨天，月结页统计跟着落到正确月份 |
| 2 | 任意一笔能改任意字段，改完汇总、占比、预算同步刷新 |
| 3 | 删除后能撤销，撤销后数据与原样一致 |
| 4 | 造 200 笔数据，按分类 + 关键词筛选仍能秒出结果，且不再只显 8 笔 |
| 5 | 模板一键带入全部字段，只改金额即可保存 |
| 6 | 同一周期规则在同一天重复打开，只补记一次 |
| 7 | 导出的 `CSV` 能用表格软件打开，导入后条数与金额一致 |
| 8 | 分享时不勾「允许更改」，对方导入后看不到任何记 / 改 / 删入口，强行触发也被拦住 |
| 9 | 切账本后，流水、月结、预算都只算当前账本 |
| 10 | 票据能看原图、能清理，清理后账目本身不丢 |
| 11 | 分享文件能被微信转发、能被本小程序导入，导入后条数与金额与分享时一致 |
| 12 | 可改副本里改一笔，操作流水立刻多一条，含署名、时间、动作、改前值改后值 |
| 13 | 操作流水只能追加，界面没有编辑删除入口；账目删了流水还在，清账本数据也还在 |
| 14 | 只读副本不产生任何改动流水，也不产生访问流水（如实说明做不到） |
| 15 | 回传合并后本机能看到对方署名与改动时间；同一笔两边都改时，双方版本都能在流水里查到 |
