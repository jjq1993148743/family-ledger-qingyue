## 一、范围裁定

| 项 | 结论 | 理由 |
|---|---|---|
| 截图 `OCR`（图片文字识别） | 不做 | 用户点名砍掉 |
| 自动同步微信 / 支付宝 / 银行流水 | 不做 | 用户点名砍掉；要登录授权、各家账单格式不一、隐私合规、接口一变就失效 |
| 多币种 | 不做 | 统一人民币 |
| 社区 | 不做 | 与记账无关 |
| `AI`（人工智能） | 基础记账不做；`wx.cloud.extend.AI`（小程序 AI 调用接口）作为**可选增强**单列 | 用户此前砍掉 `AI`，后又挂载小程序 AI 能力要求评估；落地门槛见 6.5，预检没过前不写 AI 代码 |
| 多人协作 / 成员权限体系 | 不做 | 用户点名砍掉；不邀请、不建成员账号、不设角色 |
| 「纯本地不联网」 | **不是需求，已删** | 见修订三 |
| 微信云开发 | **可用，推荐** | 用户确认「只要有数据库就行」；云开发自带云数据库、云函数、云存储，省服务器、域名与鉴权，见修订五 |
| 自建后端 + 数据库 | **备选** | 需要自己管服务器、域名备案、证书与鉴权；业务用例与表结构不变 |
| 账本分享 | **做** | 发一条分享链接，当场勾「允许对方更改」；不勾只读，勾了可改，随时能停用 |
| 操作留痕 + 整体操作流水 | **做** | 只读访问、每次改动都记「谁、服务端时间、对哪笔、改前改后」，全账本一份完整流水，存数据库 |
| 数据库主本 + 离线补传 | **做** | 数据落在库里，换设备不丢，没网也能记 |
| 除以上不做项 | 全做 | 用户确认「其他的都要」 |

说明：原有 `member`（成员：我 / 家人 / 共同）只是**账目归属标签**，用来做统计，不是账号，也不是协作身份，保留不动。

## 二、角色

| 角色 | 是谁 | 权限边界 |
|---|---|---|
| 使用者 | 拥有这本账的人，同一微信号跨设备 | 记、改、删、看、管配置、发起与停用分享、看操作流水、导出备份 |
| 分享接收方 | 点开分享链接的人，不用注册、不进成员体系 | 按链接权限：只读则只看，可改则能记改删；每次访问与改动由云函数 / 后端写进操作流水 |

## 四、业务用例

| 编号 | 谁 | 在哪个页面 | 可以干什么 | 达到什么目的 |
|---|---|---|---|---|
| A1 | 使用者 | 账本页 | 切支出 / 收入，输金额（支持 `12+8` 直接算），选分类、账户、成员、日期（可补昨天以前）、填备注、附票据照片，点「记下」 | 一次把一笔真实消费记全，不用回家补、不漏字段 |
| A2 | 使用者 | 账本页 | 选模板（买菜 / 通勤 / 工资）一键带入金额、分类、账户、备注，只改金额就存 | 高频固定支出不用每次重填 |
| A3 | 使用者 | 账本页 | 记完保留上次分类、账户、成员，只清金额和备注 | 连着记几笔不重复选 |
| A4 | 使用者 | 账本页 | 顶部看本月收入 / 支出 / 结余、预算剩余，超支标红 | 记之前就知道这个月还剩多少能花 |
| A5 | 使用者 | 账本页 | 切当前账本（日常 / 旅行 / 装修） | 专项花费不混进家庭日常账 |
| A6 | 系统 | 云函数定时触发器 / 后端定时任务 | 按周期规则定时补记到期账（房租、工资），同日同规则只补一次；不依赖打开小程序 | 固定收支不因忘记打开而漏记 |
| A7 | 使用者 | 账本页 | 点最近几笔进详情，直接编辑或删除 | 记错当场改，不用翻二级页 |
| A8 | 使用者 → 系统 | 账本页 | 没网也能记，先写本机缓存并显示「待同步」；联网后按 `client_id`（客户端幂等标识）批量补传，流水不丢一条、不重复记 | 地铁、地库、信号差照样记，且不丢数据 |
| A9 | 使用者 | 账本页 | 换手机 / 重装后用同一微信号登录，数据库里的账目、分类、模板、操作流水自动回来 | 换设备、清缓存、删小程序都不丢账 |
| B1 | 使用者 / 分享接收方 | 流水页 | 按日分组看全部账目（不再只显 8 笔），每日小计收入 / 支出 | 完整还原钱怎么花的 |
| B2 | 使用者 / 分享接收方 | 流水页 | 日历视图点某天看当天明细、跨天补记 | 对账、想起漏记的那天 |
| B3 | 使用者 / 分享接收方 | 流水页 | 按分类 / 成员 / 账户 / 账本 / 类型 / 日期 / 金额区间 / 关键词筛选 | 从几百笔里一秒找到「上周给爸买药那笔」 |
| B4 | 使用者 / 分享接收方（限可改链接） | 流水页 | 编辑任意一笔：金额、分类、账户、成员、日期、备注、票据 | 记错、选错、输错都能纠正 |
| B5 | 使用者 / 分享接收方（限可改链接） | 流水页 | 删除后 5 秒内撤销，或进回收站保留 7 天 | 手滑删了不丢数据 |
| B6 | 使用者 / 分享接收方 | 流水页 | 点开票据照片看原图 | 核对小票、报销有凭 |
| B7 | 分享接收方 | 流水页（数据库同一本账） | 按链接权限：不勾只读，记改删入口全隐藏且云函数 / 后端拒绝写入；勾了可改就能记改删，每次改动在同一事务里写进操作流水 | 只读是真只读，可改是笔笔留痕，谁在什么时候动的说得清 |
| C1 | 使用者 / 分享接收方 | 月结页 | 左右切月份，看收入 / 支出 / 结余、笔数 | 月底复盘有个准数 |
| C2 | 使用者 / 分享接收方 | 月结页 | 按分类 / 成员 / 账户 / 账本看支出占比与排行 | 知道钱主要花在哪个口子、谁花的 |
| C3 | 使用者 / 分享接收方 | 月结页 | 看总预算与分类预算执行、超支标红、对比上月趋势 | 下个月知道该收哪一刀 |
| C4 | 使用者 | 月结页 | 点分类下钻到该分类的流水 | 从「伙食花了 2000」直接看到哪笔记多了 |
| D1 | 使用者 | 设置页 | 增删改分类（名称 / 图标 / 颜色 / 排序），支出收入各一套 | 分类贴合自家口径，不再被写死的 7 + 5 个困住 |
| D2 | 使用者 | 设置页 | 管账户（现金 / 微信 / 支付宝 / 银行卡），可停用不删历史 | 记账能选资金出处，停用旧卡不丢旧账 |
| D3 | 使用者 | 设置页 | 管账本（建 / 改名 / 切换 / 删，删除二次确认并说明数据去向） | 旅行、装修专项账分开算 |
| D4 | 使用者 | 设置页 | 管模板（把常记的一笔存成模板、排序、删除） | 把 A2 的提速能力自己攒出来 |
| D5 | 使用者 | 设置页 | 管周期账（金额 / 分类 / 账户 / 周期 / 起始日 / 启停） | 房租、工资、话费不用月月手敲 |
| D6 | 使用者 | 设置页 · 分享账本弹层 | 选账本 → 勾「允许对方更改」→ 给访问者填个署名（用于留痕，如「家人」）→ 选可见范围 → 生成分享链接 → 转发微信 | 不建账号、不拉人协作，一条链接把账交出去，改不改当场定 |
| D7 | 使用者 | 设置页 | 设总预算、各分类预算、超支提醒开关 | 把 A4 / C3 的阈值定下来 |
| D8 | 使用者 | 设置页 | 导出 `CSV`（逗号分隔表格，按时间 / 账本筛选）并转发或复制，可导入恢复 | 数据库之外再多一层保险 |
| D9 | 使用者 | 设置页 | 看存储占用、清理票据图片、清空账本数据（操作流水只追加不随清空消失） | 不被图片撑爆，留痕不被顺手抹掉 |
| D10 | 分享接收方 | 微信里点开分享链接 | 不用注册、不用导入文件，按权限直接看数据库里同一本账；只读就只看，可改就能补能改 | 拿到就能看或就能补，不用折腾文件来回传 |
| D11 | 使用者 | 设置页 · 分享管理 | 看已发出的链接、权限、访问与改动记录；可改权限或一键停用 | 随时收回，不留后门 |
| E1 | 使用者 / 分享接收方 | 操作流水页 | 按时间倒序看整本账从建账到现在的全部操作：谁、服务端时间、对哪笔、做了什么（访问 / 记一笔 / 改 / 删 / 分享 / 停用 / 补记 / 同步）、改前值改后值 | 账上任何变动、谁来看过，都能追到人追到时间 |
| E2 | 使用者 / 分享接收方 | 操作流水页 | 按操作人、动作类型、时间范围、关键词筛选，点一条跳到对应那笔账 | 几百条流水里一秒定位「这数是谁改的」 |
| E3 | 使用者 | 操作流水页 | 单独导出操作流水 | 留档、对账有凭 |
| E4 | 系统 | 云函数 / 后端 + 所有写操作处 | 每次访问 / 新增 / 修改 / 删除 / 撤销 / 分享 / 停用 / 导入 / 补记 / 同步，与业务数据在同一事务里追加一条流水：只追加，接口不提供改删，账目删了流水仍在 | 留痕靠系统自动记，不靠人自觉，也抹不掉 |

## 五、约束与落地替代

| 想做的事 | 依据 / 约束 | 落地办法 |
|---|---|---|
| 数据不丢 | 用户明确要求换手机、清缓存也不能没 | 数据库存主本，本机 `wx.setStorageSync`（微信本地缓存接口）只作离线暂存；同一微信号跨设备登录自动拉回 |
| 后端形态 | 用户 2026-11-04 澄清「云开发那套也可以，只要有数据库就行」 | **云开发优先**：云函数 + 云数据库 + 云存储；自建后端 + 数据库为备选。两者业务用例与表结构一致，见第六节 |
| 云开发有数据库 | 官方文档：云数据库含文档型（`MongoDB`，分布式文档数据库）与 `MySQL` 型（`TDSQL`，关系型数据库），可单用或并用 | 选 `MySQL` 型，6.2 的 10 张表直接复用；若改选文档型，则表改为集合（文档），需重做结构 |
| 免域名与天然鉴权 | 云开发走 `wx.cloud`（云开发接口）微信私有链路；云函数上下文直接拿 `openid`（微信用户唯一标识） | 不用买服务器、不用域名备案、不用配 `request` 合法域名（允许请求的服务器域名）、不用自建会话；**仅自建后端备选方案才需 `HTTPS`（加密传输协议）+ 备案域名** |
| 开通前提 | `project.config.json:7` 仍是 `touristappid`（游客测试号） | 换正经 `AppID`（小程序账号标识）、开通云开发环境、拿 `envId`（云开发环境标识）填进 `app.js`（小程序入口），`f:\family-ledger-qingyue\README.md:18` |
| 「别人访问」 | 数据库里是同一本账，不用发文件、导副本 | 分享链接带 `token`（访问凭证），云函数 / 后端按 `editable`（可否更改）校验读写；只读链接连写请求也拒绝 |
| 访问留痕 | 云函数 / 后端能记 | 只读访问也留一条「谁、什么时候、看了哪本」 |
| 「谁」怎么来 | 不建账号、不拿微信昵称 | 分享时填署名写进链接 `actor`（操作人署名）；这是留痕标识，不是实名认证 |
| 「什么时候」 | 服务端统一时间 | 用服务端时间，不受手机本地时间影响 |
| 整体操作流水 | 数据库集中存 | 本机、分享接收方的动作都写进同一张流水表 / 集合，不用回传、不用合并 |
| 多人协作仍不做 | 用户点名砍掉 | 不邀请、不建成员体系、不设角色；只有一条可停用的分享链接加权限开关 |
| 并发冲突 | 两边可能同时改同一笔 | 按服务端时间后改覆盖，双方版本都写进流水，不静默丢；冲突条目在 E2 可筛出 |
| 周期账「自动」 | 云函数定时触发器 | 由定时触发的云函数扫描规则补记（A6），不依赖打开小程序 |
| 票据照片 | 图片不适合塞数据库字段 | 存云存储，`entries.image_path`（票据路径字段）只存文件标识，D9 可清理 |
| 超支「提醒」 | 订阅消息要用户授权 | 仍做页内标红（A4 / C3），不强制推送 |
| 被砍掉的那几项 | 用户点名 | 语音 / 一句话 / `OCR` / 银行流水自动同步 / 多币种 / 社区一律不做；`AI`（人工智能）仅作为可选增强且预检通过后才动，见 6.5 |
| 老数据兼容 | 现有记录字段固定（`miniprogram/pages/ledger/ledger.js:102`），日期写死今天（`:104`），只能删不能改（`miniprogram/utils/store.js:34`） | 新字段读取时补默认值，不迁移；`month`（月份）按 `date`（日期）重算；老账目不伪造历史流水 |

## 六、后端与数据库

### 6.1 分层

| 层 | 干什么 | 云开发落地（推荐） | 自建后端备选 |
|---|---|---|---|
| 小程序前端 | 页面、交互、本机缓存（离线暂存） | `wx.cloud` 直接调云函数 / 云数据库 | `wx.request`（网络请求接口）调自建接口 |
| 接口层 | 鉴权、参数校验、分享链接读写权限校验、`CSV`（逗号分隔表格）导出 | 云函数入口 | 控制器 |
| 业务层 | 记账、汇总、月结、预算、周期补记、冲突处理、写操作流水（同事务） | 云函数业务逻辑 | 服务层 |
| 数据层 | 账目与操作流水同一事务写入 | 云数据库 | 自建数据库 |
| 定时任务 | 扫描周期规则补记，按 `last_fired_at`（上次触发时间）去重 | 云函数定时触发器 | 服务端定时任务 |

### 6.2 数据表（选 `MySQL` 型云数据库可直接复用）

| 表 | 中文 | 关键字段 | 用途 |
|---|---|---|---|
| `users` | 用户表 | `id`（主键）、`openid`（微信用户唯一标识）、`created_at`（创建时间） | 认人，换设备靠它 |
| `books` | 账本表 | `id`（主键）、`user_id`（所属用户）、`name`（名称）、`is_default`（是否默认）、`deleted_at`（删除时间） | 日常 / 旅行 / 装修 |
| `categories` | 分类表 | `id`（主键）、`book_id`（账本标识）、`type`（支出或收入）、`name`（名称）、`icon`（图标）、`color`（颜色）、`sort`（排序） | 自定义分类 |
| `accounts` | 账户表 | `id`（主键）、`book_id`（账本标识）、`name`（名称）、`enabled`（是否启用） | 现金 / 微信 / 银行卡 |
| `entries` | **账目表（核心）** | `id`（主键）、`book_id`（账本标识）、`category_id`（分类标识）、`account_id`（账户标识）、`member`（成员标签）、`type`（类型）、`amount`（金额）、`date`（日期）、`month`（月份）、`note`（备注）、`image_path`（票据路径）、`client_id`（客户端幂等标识）、`created_by`（创建人）、`created_at`（创建时间）、`updated_at`（修改时间）、`deleted_at`（删除时间） | 每一笔账 |
| `templates` | 常用模板表 | `id`（主键）、`book_id`（账本标识）、`name`（名称）、`payload`（预填内容）、`sort`（排序） | 一键记 |
| `recurring_rules` | 周期规则表 | `id`（主键）、`book_id`（账本标识）、`payload`（账目内容）、`cycle`（周期）、`start_date`（起始日）、`enabled`（是否启用）、`last_fired_at`（上次触发时间） | 房租工资定时补记 |
| `budgets` | 预算表 | `id`（主键）、`book_id`（账本标识）、`category_id`（分类标识，空为总预算）、`amount`（金额）、`period`（周期） | 总预算 / 分类预算 |
| `share_links` | 分享链接表 | `id`（主键）、`book_id`（账本标识）、`token`（访问凭证）、`editable`（可否更改）、`actor`（访问者署名）、`scope`（可见范围）、`expires_at`（过期时间）、`revoked_at`（停用时间） | 只读 / 可改权限、随时停用 |
| `operation_logs` | **操作流水表** | `id`（主键）、`book_id`（账本标识）、`actor`（谁）、`action`（动作）、`entry_id`（哪笔账）、`before`（改前值）、`after`（改后值）、`source`（来源）、`created_at`（服务端时间） | 整体留痕，只追加不改删 |

若改选文档型数据库，以上每张表对应一个集合（文档），`_id` 为主键，字段基本一致，但关联查询与事务写法要按文档型重写。

### 6.3 主要接口

| 接口 | 方法（动作） | 云开发落地 | 用途 |
|---|---|---|---|
| `/api/auth/login` | 登录 | 免建，云函数上下文直接取 `openid`（微信用户唯一标识） | 认人 |
| `/api/entries` | 查询 / 新增 | 同名云函数 | 拉流水、记一笔 |
| `/api/entries/{id}` | 改 / 删 | 同名云函数 | 编辑、软删除 |
| `/api/entries/sync` | 批量补传 | 同名云函数 | 离线记账按 `client_id`（客户端幂等标识）去重提交，A8 |
| `/api/books`、`/api/categories`、`/api/accounts` | 增删改查 | 同名云函数 | 配置管理 |
| `/api/templates`、`/api/recurring-rules`、`/api/budgets` | 增删改查 | 同名云函数 | 模板、周期、预算 |
| `/api/monthly?month=` | 查询 | 同名云函数 | 服务端算月结汇总与占比 |
| `/api/share-links` | 建 / 改 / 停用 | 同名云函数 | 生成链接、改权限、一键停用 |
| `/api/s/{token}` | 读 / 写 | 同名云函数 | 按 `token`（访问凭证）权限访问同一本账 |
| `/api/operation-logs` | 查询 / 导出 | 同名云函数 | 整体操作流水 |

云开发路线前端用 `wx.cloud.callFunction`（云函数调用接口）按名字调用，不需要 `HTTPS`（加密传输协议）接口与合法域名；自建后端路线才按表中路径起 `HTTP`（网页传输协议）服务。

### 6.4 云开发落地清单

| 云开发能力 | 对应本设计 | 好处 |
|---|---|---|
| 云数据库 `MySQL` 型 | 6.2 的 10 张表原样建库 | 之前的表设计不推翻，账目与流水能同事务 |
| 云函数 | 6.1 接口层 + 业务层，6.3 逐个映射 | 不买服务器、不运维，微信私有链路天然鉴权 |
| 云存储 | 票据图片，账目只存文件标识 | 不挤数据库，D9 可清理 |
| 定时触发器 | A6 周期账补记 | 不用打开小程序也能补 |
| `wx.cloud.init`（云开发初始化） | `app.js`（小程序入口）填 `envId`（云开发环境标识） | 一处配置，全端可用 |
| `wx.cloud.extend.AI`（小程序 AI 调用接口） | 可选增强，见 6.5 | 云开发环境下才可用，自建后端路线用不上 |

### 6.5 小程序 AI 能力的落地门槛（可选增强，本轮不写代码）

用户挂载的 `ai-model-wechat` 能力依赖云开发环境，与云开发优先的选型正好一致；但该能力强制两步预检，顺序固定，未通过前不得写任何业务代码。

| 步骤 | 要求 | 当前状态 |
|---|---|---|
| 预检① 计费资格 | 先查小程序成长计划（`DescribeActivityInfo`，活动信息查询）；未加入再查 Token Credits 资源包（`DescribeEnvPostpayPackage`，资源包查询） | 没有 `envId`（云开发环境标识）、当前环境也无对应 `callCloudApi`（云接口调用工具），**跑不了** |
| 预检② 组就绪 | `DescribeAIModels`（模型组查询）确认组存在、状态开启、目标模型在列表里；缺模型则 `DescribeManagedAIModelList`（可选模型目录）查准名字，再 `UpdateAIModel`（启用模型，`Models` 是**全量替换**）开启 | 未开环境，跑不了 |
| 通过后才可写 | `wx.cloud.extend.AI.createModel(...)` 的入参只能是 `hunyuan-exp`（成长计划组）、`cloudbase`（主托管组）或 `custom-*`（自定义组），**不能**填厂商名或模型名；具体模型 ID 放 `model` 字段 | 本轮不写 |
| 调用形态 | `generateText`（一次性生成）返回原始响应，取 `choices[0].message.content`；`streamText`（流式生成）参数必须包在 `data: {...}` 里，可用 `onText` / `onEvent` / `onFinish`（回调），遍历 `eventStream`（事件流）要判断 `[DONE]`（结束标记） | 本轮不写 |
| 基础库 | `wx.cloud.extend.AI` 需微信基础库 3.7.1+，低版本为 `undefined`（未定义），别当模型问题排查 | 待建环境时核对 |

## 八、验收口径

| 编号 | 条件 |
|---|---|
| 1 | 能把一笔账记到昨天，月结页统计跟着落到正确月份 |
| 2 | 任意一笔能改任意字段，改完汇总、占比、预算同步刷新 |
| 3 | 删除后能撤销，撤销后数据与原样一致 |
| 4 | 造 200 笔数据，按分类 + 关键词筛选仍能秒出结果，且不再只显 8 笔 |
| 5 | 模板一键带入全部字段，只改金额即可保存 |
| 6 | 同一周期规则在同一天只补记一次 |
| 7 | 导出的 `CSV` 能用表格软件打开，导入后条数与金额一致 |
| 8 | 分享时不勾「允许更改」，对方打开看不到记 / 改 / 删入口，直接调写接口也被云函数 / 后端拒绝 |
| 9 | 切账本后，流水、月结、预算都只算当前账本 |
| 10 | 票据能看原图、能清理，清理后账目本身不丢 |
| 11 | 一键停用分享链接后，原链接立刻失效，停用动作写进操作流水表 |
| 12 | 可改链接里改一笔，操作流水表立刻多一条，含署名、服务端时间、动作、改前改后 |
| 13 | 操作流水只能追加，接口不提供改删；账目删了流水还在，清账本数据也还在 |
| 14 | 只读链接打开一次，操作流水表留下一条访问记录（谁、服务端时间、看了哪本） |
| 15 | 断网记一笔，联网后按 `client_id`（客户端幂等标识）补传，重复补传不产生第二笔，流水不丢 |
| 16 | 换设备用同一微信号登录，账目、分类、模板、操作流水条数与金额完全一致 |
| 17 | 账目写入与操作流水写入在同一事务里，任一失败整笔回滚，不出现「账改了没留痕」 |
| 18 | 云函数上下文能直接拿到 `openid`（微信用户唯一标识），不需要额外登录接口与会话令牌 |
